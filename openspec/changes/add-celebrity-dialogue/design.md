## Context

平台当前只有 `home`、`modules`、`chat` 三类顶级页面。通用 AI 顾问通过 `/chat/init/general` 创建会话，再复用 `/chat/send` 与 `/chat/stream`；后端将 bootstrap 保存到 `AgentSessionStore`，由 `ChatOrchestrator` 传给 DeepSeek 或 Cursor。现有发送路由在调用模型前统一执行术数范围检查，并明确拒绝普通角色扮演，因此人物对话不能仅靠新增前端场景或追加提示词实现。

王阳明 Skill 是 Markdown 人物方法论包，包含角色规则、思想模型、表达 DNA、适用边界、研究资料与 MIT 许可证。它是内容来源而非受信任的可执行插件。人物对话需要同时改动前端导航、会话类型、后端范围策略和内容包加载，是跨模块的新架构能力。

## Goals / Non-Goals

**Goals:**

- 提供独立的“名人对话”入口、人物目录和沉浸式人物对话体验。
- 建立无需为每个人物改业务代码的内置人物包格式，并以王阳明作为首个完整样例。
- 复用现有模型、流式输出、额度和会话历史，同时让人物会话与术数会话使用不同范围规则。
- 明确区分人物原典、资料摘要与模型推断，避免把 AI 生成内容伪装成历史事实或本人原话。
- 对外部 Skill 采用静态导入、字段白名单、大小限制和许可证保留，禁止运行任意代码。
- 保持桌面与移动端的现有编辑部视觉体系和可访问性基线。

**Non-Goals:**

- 首版不提供用户上传、URL 在线安装或运行时热加载 Skill。
- 首版不接入在世人物，不制作声音克隆、数字人视频或真人身份认证效果。
- 首版不为人物资料建设新的向量数据库；人物核心思想和来源目录随静态人物包发布。
- 不允许人物身份绕过医疗、法律、金融等高风险建议边界。
- 不改变现有术数顾问、排盘和融合会话的输出范围。

## Decisions

### 1. 使用版本化静态人物包，而不是直接安装外部 Skill

后端新增只读人物包目录，每个人物使用固定结构：

```text
personas/<persona-id>/
├── manifest.json       # id、名称、年代、简介、状态、版本、许可证
├── prompt.md           # 审核后的核心思想、交互协议和表达规则
├── sources.json        # 来源标题、类型、说明与可选链接
├── starters.json       # 开场问题与主题标签
└── LICENSE             # 上游许可证或归属声明
```

`manifest.json` 使用 JSON，避免新增 YAML 解析依赖。注册表只接受代码内允许的目录和字段，校验 ID、文本大小、文件类型、人物状态和必需披露文案。外部 Skill 的脚本、命令、工具声明和未知文件一律不加载。

替代方案是运行 `npx skills add` 后让模型直接读取 Skill。该方案依赖开发工具运行时、无法控制供应链内容，也无法为网页用户稳定复现，因此不采用。

### 2. 新增人物会话类型，复用现有发送与流式链路

新增：

- `GET /personas`：返回可用人物卡片的公开元数据。
- `GET /personas/{persona_id}`：返回人物详情、主题、开场问题和来源目录，不返回完整系统提示词。
- `POST /chat/init/persona`：校验人物 ID，编译人物 bootstrap，创建会话并记录 `session_kind=persona` 和 `persona_id`。

发送仍复用 `/chat/send` 和 `/chat/stream`。`AgentSessionStore` 为会话保存受控元数据；发送路由根据服务端会话元数据选择术数或人物范围策略，不信任客户端声明的会话类型。

替代方案是复制一套 `/persona/chat/send` 和 `/persona/chat/stream`。这会重复额度、SSE、模型选择和历史逻辑，因此不采用。

### 3. 人物提示词由固定安全合同和人物内容分层编译

人物 bootstrap 按以下顺序组成：

1. 平台不可覆盖的身份披露、事实边界和高风险建议合同。
2. 人物包中的思想模型、适用范围、表达规则和退出规则。
3. 来源目录摘要及“仅将可核实原文标记为引用”的规则。
4. 当前对话模式与可选首问。

王阳明人物包从上游 Skill 提炼，而不是逐字把全部研究资料放入每次请求。核心 bootstrap 控制在可审计的大小上限内，研究目录用于前端溯源；后续若人物数量和资料规模增长，再单独评估人物 RAG。

### 4. 首版人物范围与术数范围隔离

人物会话允许人生选择、学习、修养、领导、思想史和人物相关问题，不再触发现有“角色扮演”拒绝项。人物超出擅长范围时须承认边界并从其思想框架提供有限视角；医疗、法律和金融具体结论仍需拒绝替代专业意见。

普通术数会话继续使用现有 `CHAT_SCOPE_GUARDRAIL` 和关键字检查。不存在、过期或未标记为人物类型的会话不得使用人物范围策略。

### 5. 产品入口使用独立页面，聊天运行时尽量复用

`ProductPageId` 新增 `personas`，顶部导航显示“名人对话”。页面分为人物大厅和人物会话两种状态：

- 人物大厅：王阳明人物卡、思想主题、适用问题和史料模拟说明。
- 人物会话：人物身份栏、首次披露、开场问题、流式消息、模型选择、来源抽屉和返回大厅。

消息渲染、流式状态、复制、停止生成和模型选择复用现有 `AssistantChatRuntime`。人物会话记录增加 `source: persona`、`personaId` 和人物副标题，避免与术数最近会话混淆。

### 6. 史料透明度优先于沉浸感

人物可以使用第一人称风格化回应，但页面始终可见“AI 思想模拟”标记。只有人物包明确收录且带来源的文本可以作为原典引用；其余内容必须作为分析、转述或模拟表达，不得声称是人物真实说过的话或经历的精确复述。

首版人物注册表只接受 `historical-deceased` 状态。未来是否支持在世人物需要新的风险评审和 OpenSpec 变更。

## Risks / Trade-offs

- **角色提示词可能产生虚构引文** → 固定引用规则、来源抽屉、测试虚构引用提示，并在 UI 持续显示模拟身份。
- **人物 prompt 过长增加延迟和费用** → 提炼核心内容、设置包大小上限，首版不将完整研究文档逐轮注入。
- **人物范围策略被客户端伪造** → 会话类型和人物 ID仅由服务端创建并存储，发送时从服务端会话读取。
- **外部 Skill 含恶意或越权指令** → 只允许人工审核后的 Markdown/JSON 内容进入内置包，不执行命令、脚本或工具声明。
- **复用聊天历史导致类型混淆** → 会话记录增加来源判别字段，人物页面只展示人物会话。
- **王阳明思想被过度美化或简化** → 保留 Skill 中的局限、批评和适用边界，来源页同时展示一手来源和现代研究。
- **名称“名人对话”让用户误以为真人** → 导航保留易懂名称，但卡片、会话头和首条消息统一标注“基于史料的 AI 思想模拟”。

## Migration Plan

1. 先增加人物包注册表、王阳明静态包和后端单元测试，不开放导航入口。
2. 增加人物会话接口和服务端会话类型，验证术数范围策略没有回归。
3. 增加前端人物大厅与对话工作区，在局域网环境完成桌面和移动端浏览器验证。
4. 将功能随现有本地部署发布；无需数据库迁移。
5. 若上线后出现问题，可隐藏 `personas` 导航并禁用人物注册表，现有术数会话不受影响。

## Open Questions

- 首版产品名称使用用户提出的“名人对话”；若后续人物均为传统思想家，可再评估是否改为“先贤对话”。
- 人物 RAG、人物包管理后台、用户导入 Skill 和更多人物均留作后续独立变更。
