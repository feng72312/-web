## Context

现有实现以一个经过人工整理的王阳明人物包为中心：注册表只接受 `historical-deceased`，人物 API 一次返回全部人物，前端也按单卡片设计。awesome-nuwa 当前 README 声称包含 159 位人物和 18 个领域，但目录明细混合 `nuwa-skills/*` 与 `alchaincyf/*` 仓库，且摘要计数与表格行数存在漂移风险。部分人物仍在世，不能沿用历史人物第一人称模拟合同。

本变更把外部目录视为“候选来源”，而不是运行时依赖或可信代码。生产服务不得在用户请求期间访问 GitHub，也不得执行上游 Skill 中的命令、脚本或工具说明。

## Goals / Non-Goals

**Goals:**

- 全量记录 awesome-nuwa 目录条目，并保持 18 个领域分类和上游可追溯性。
- 通过可重复、可审计的离线流程生成本地目录和人物包。
- 让已故人物与在世人物使用不同的身份表达合同。
- 支持百余人物的搜索、分类筛选、状态提示和移动端浏览。
- 保持王阳明人物包、既有会话 API 和本地历史记录兼容。

**Non-Goals:**

- 不在运行时自动追随 awesome-nuwa 最新提交。
- 不执行上游仓库中的代码、脚本、工具调用或安装命令。
- 不承诺所有目录条目在授权或资料不完整时立即开放对话。
- 不加入人物照片、声音克隆、签名或其他容易被理解为本人授权的资产。
- 不把人物观点当作医疗、法律、金融交易或实时事实的专业结论。

## Decisions

### 1. 固定上游快照，离线导入

新增导入工具读取固定 commit 的 awesome-nuwa README，解析“分类/人物/领域/仓库”四元组并生成 `catalog-source.json`。工具随后以只读方式拉取每个人物仓库的固定 commit，只读取白名单文件（`SKILL.md`、`README.md`、`LICENSE`、`references/*.md`），限制单文件和总大小，不跟随任意脚本。

选择固定快照而不是运行时 GitHub API，是为了避免目录漂移、限流、供应链变化和服务启动失败。每次更新都会先生成审计报告，人工查看差异后才替换生产快照。

### 2. 目录记录与可对话人物包分离

所有上游条目都会进入轻量目录记录，字段包括分类、主题、仓库、固定 commit、生命状态、授权状态、审核状态和可用状态。只有通过授权、来源和安全校验的记录才生成完整人物包并允许 `POST /chat/init/persona`。

这样可以满足“全部收录和分类”，同时不会把未审核条目伪装成可用人物。前端对 `review_required` 或 `unavailable` 显示原因和上游链接，不提供创建会话按钮。

### 3. 两种人物交互合同

- `historical_simulation`：仅用于已故人物，允许在持续披露下使用第一人称思想模拟，但原典引用必须来自人物包来源目录。
- `public_framework`：用于在世或身份不确定人物，只能说“从公开资料归纳的某某思维框架”，不得自称本人、虚构亲历、代言、实时观点、私生活或未公开信息。

生命状态和交互模式由服务端人物包决定，客户端不能覆盖。身份无法可靠确认时默认采用更严格的 `public_framework`，并可由审核状态进一步禁用。

### 4. 分类是稳定 ID，名称是展示数据

18 个领域使用稳定的 ASCII category ID，同时保留上游中文标题和排序。人物可有一个主分类及多个主题标签。API 返回分类计数，并支持 `category`、`query`、`availability` 参数；159 条数据规模下服务端内存过滤足够，无需数据库或搜索引擎。

### 5. 生成物保留归属和审计证据

每个人物记录保存源仓库 URL、commit SHA、许可证名称、许可证 URL、原作者归属和导入时间。生成 prompt 时只提取思维框架和表达约束，不复制上游示例长文。来源目录将上游 research 条目转成简要引用记录，并保留“原典/研究/上游/批判边界”区分。

### 6. 前端采用目录优先的渐进浏览

人物馆首屏提供分类横向导航、搜索框、可用状态筛选和动态计数；人物卡按分类虚拟分组/分页展示，避免一次渲染所有详情。详情仍按需请求。人物对话工作区沿用现有流式运行时，按 `interactionMode` 改变披露文本和视觉标签。

## Risks / Trade-offs

- **上游 README 的 159/18 声明与实际表格可能不一致** → 解析器以实际唯一仓库条目为准，生成计数漂移报告，并在构建中阻止静默增删。
- **159 个仓库逐一拉取容易受限流或中途失败** → 支持缓存、断点续跑、并发上限和失败清单；生产构建只使用已提交快照。
- **MIT 仓库仍可能引用受版权保护的书籍或讲话** → 仅保留短元数据和框架化转述，不批量复制研究全文；原句引用继续由来源白名单约束。
- **在世人物对话被误认为本人表态** → 强制第三人称“公开思想框架”合同、持续标签和禁止第一人称；服务端记录交互模式，前端参数不可提升权限。
- **人物卡过多造成页面拥挤和性能下降** → 列表使用筛选、分页/分组懒加载，详情按需请求，移动端不渲染桌面侧栏。
- **上游 Skill 质量不一** → 导入仅提供候选，自动校验后仍需抽样审阅；未达到来源和边界要求的条目保持不可对话。

## Migration Plan

1. 保持王阳明现有 ID 与包内容不变，先引入新目录 schema 和兼容读取。
2. 生成并审阅 awesome-nuwa 固定快照、分类统计和授权审计报告。
3. 批量生成通过校验的人物包，运行注册表、身份合同和 API 测试。
4. 发布新版人物馆，默认仍突出王阳明，同时开放分类搜索。
5. 通过本地服务器灰度验证后替换生产静态构建；回滚时可恢复旧目录快照和前端构建，既有会话不受影响。

## Open Questions

- 后续上游新增人物是否自动进入“待审核”，还是每次由管理员显式触发导入；本次默认采用显式触发。
- 人物质量评分与首页推荐排序暂采用人工配置，后续有真实使用数据后再考虑自动排序。
