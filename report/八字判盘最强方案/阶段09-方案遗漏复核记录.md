## 仍未完成或需下一轮深化

### 1. 格局规则图谱仍偏薄

当前 geju 只有 8 个第一批节点, 还不足以覆盖《子平真诠》的细分格局, 例如正官配印、财格生官、伤官佩印、合煞留官、杂气格、外格取舍等喵

建议下一轮优先做 `Phase 10: 子平真诠第二批格局规则`, 输出更多 `geju:*` 节点并补 conflictsWith / priority / condition 喵

### 2. RAG + benchmark 联动仍缺真实检索基线

当前 val 20 题离线 baseline 未启用 RAG, 因此 primaryEvidence=0, caseOverreach=20 是预期监控信号, 不是生产结论喵

下一步应启动本地 RAG 服务后执行:

```bash
cd code/backend
python scripts/val_judgement_baseline_local.py --split val --limit 20 --rag --output ../../report/八字判盘最强方案/val_judgement_baseline_rag.json
```

验收目标是 primaryEvidence 上升, caseOverreach 明显下降喵

### 3. FastAPI 全应用 smoke 仍受 cursor_sdk 依赖影响

当前已用 `smoke_judgement_local.py` 绕过 FastAPI app 初始化, 但 `/api/v1/paipan/judgement` 的完整 TestClient smoke 仍会被 `cursor_sdk` 导入阻塞喵

下一步可选方案是将 Cursor SDK 相关路由延迟导入, 或为本地测试提供可选依赖兜底, 这样才能做完整 API smoke 喵

### 4. AI 解读与 ruleId 的段落级绑定仍不够深

前端已展示 ruleIds 和证据链, benchmark prompt 也注入 judgement block, 但 AI 最终解读段落还没有强制逐段绑定 ruleId / evidenceChain 引用喵

下一轮可在 `prompts.py` / interpret 输出 schema 中要求每段附 `ruleIdRefs`, 前端再做锚点展示喵

### 5. case schema 仍是浅结构

当前 case 库已能禁止越权, 但 `structureTags` 主要来自干支和关键词, 尚未达到命例结构化经验库的理想状态喵

下一步可补 `eventYear`, `observedEvent`, `chartPattern`, `luckTrigger`, `doNotApplyReason`, 并抽样人工复核喵

### 6. 规则抽取质量需人工校验

当前四类抽取脚本是自动抽取第一批节点, 部分古籍段落可能包含目录或上下文噪声; safeAutoAnswer 已保持 false, 但要上线强断语仍需人工复核喵

建议建立 `reviewedAt` 和 `reviewerNotes` 流程, 只允许 reviewed 节点进入强裁判喵

### 7. 云端部署未做

这是按当前用户指令暂缓, 不算本地阶段阻塞; 但上线前仍需补 CloudBase 部署、线上 RAG health、线上 `/paipan/judgement` smoke 和前端截图喵
